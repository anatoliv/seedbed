01Ahead of time, not at copy time

A good prompt is long, specific and model-shaped.
Writing one every time is why you don't.

So in practice you type the short version and accept a worse answer. Seedbed splits the two jobs: you own the seeds, and the tool owns the expansions. Rendering happens in build, not between ⌘C and ⌘V.

Copy is a file read

The render already exists, so copying is instant, works on a plane, and puts no API call between you and the paste. A bad render is caught before it reaches a worker agent, not after.

One file per seed per model

Editing a seed marks its renders stale; it never overwrites them. Each render records the seed hash, the guidance hash, the enhancer and the date, so build only spends on what moved.

Placeholders survive

A seed like fix {{BUG}} in {{PROJECT}} keeps its blanks through the render. Copying opens a small form, one field per blank, each remembering the values you used before.

Why files and git

Prompts change slowly and need to exist on more than one computer. Git gives sharing, history, backup and conflict resolution with no server, and it works away from your own network. Renders are committed too, so when a vendor's guidance moves, git diff shows exactly how the expansion changed. You review a diff rather than trusting a black box.

  • No dependencies. Standard library only; TOML frontmatter parsed with tomllib. Python 3.11 or newer.
  • Degraded guidance is refused, not absorbed. If a vendor page cannot be read, build stops rather than quietly rendering on less input than it had.
  • Machine-local by design. Copy counts and the values you typed into placeholders stay out of the repository, so two Macs never fight over them.

02Same seed, four targets

Four models, four different prompts.
That difference is the point.

A frontier model degrades when you over-specify; an open-weight model needs numbered steps, an output format and an example. The same five words render as 182 words of outcome-focused prose for one and 698 words of procedure for another. A target is data, not a vendor account: rendering for GPT or Llama never calls OpenAI or Meta.

1. **Reproduce first.** Locate the relevant code by searching the repo. Run the failing case, the existing test, the command, or a minimal script you write, and capture the actual output. Do not edit any source file until you have observed the failure yourself.

03What we measured

Does a tailored prompt beat the raw seed?
It depends on the model, and that is the finding.

The premise was checked before this page was written: four tasks with known right answers, each given to the same model twice, once as the five-word seed and once as that model's render. Criteria were registered before anything ran. Both results are published, including the one that did not support the tool.

claude-opus-5No advantage
0 of 4tasks where the render beat the seed on correctness

Both conditions found the true mechanism wherever it was findable. The render explained more thoroughly and refused more; the seed delivered more working code. On a strong model, tailoring changed risk posture, not correctness.

If you already pay for a frontier model, the honest advice is: type the short prompt. Seedbed is not going to make it answer better.
qwen3-vl-30bRender won
3 of 4tasks won by the render · 9 of 12 criteria against 5 of 12

The raw seed produced five confident fabrications on one task and skipped the requested test on both fix tasks. The render invented nothing, named nine things it could not see, wrote real tests both times, and did it in 44% fewer words.

Raw seed
"likely using SHA-256 … the file format is likely YAML-like … the save method would likely…"
Render
"The Render class is declared but not defined in the provided code." Nine times, in different words.
What this does and does not settle. It settles that the enhancer earns its cost where the model needs scaffolding and not where it does not. It is one run per model at temperature 0, scored by one reader against pre-registered criteria, on four tasks. Both runs failed the same task in the same way, which led to a design change: a seed now declares whether it will be pasted into an agent with a checkout or a chat window with a snippet, and the render is built for that context. The raw outputs, inputs and scoring are on the evidence page, so the scoring can be disagreed with rather than taken on trust.

05Let an agent ask for a prompt

Your agent fetches the prompt it needs,
instead of you copying one across.

The Mac app can run an MCP server. Switch it on in Settings, press Copy configuration, paste that into Claude Code, Cursor or Claude Desktop, and the agent has a library it can search.

find_prompt takes a description, not a name. An agent asking for "something for reviewing a diff before I merge" gets the prompt titled Review my diff. A text match answers most asks on its own in well under a tenth of a second; only when it cannot choose does the ask go to the enhancer to be settled. Every prompt is also exposed through MCP's own prompts/list and prompts/get.

  • find_prompt
  • get_prompt
  • list_prompts
  • list_models
  • build_prompt
  • Loopback only, and a bearer token. Both, not either. Nothing on your network can reach it, and every request must carry the token, which lives in the login Keychain.
  • A second, read-only token can look prompts up but can never call build_prompt, so a client you have not decided to trust cannot spend an LLM call. It is not even shown that tool.
  • Wrong tokens lock out after ten tries, doubling from one minute to fifteen, while a correct token is still always served. A request whose Host or Origin is not this Mac is refused, with the reason in the response.

Installing the app is half the job

Seedbed is a front end and does not carry the prompts. It needs a checkout of the repository, which is the library, and Python 3.11 or newer for tomllib. The DMG says so in Before you start.txt, and a copy with neither reports an empty library rather than pretending it has one.

mkdir -p "$HOME/Library/Application Support/Seedbed"
git clone https://github.com/anatoliv/seedbed \
  "$HOME/Library/Application Support/Seedbed/Library"

What it asks for, and what it never sends

Pasting into the app you came from needs the Accessibility permission, which macOS asks for the first time you use it. Without it Seedbed copies to the clipboard and tells you why it did not paste.

Crash reports are off. If you turn them on, they carry the stack trace and the versions, and never a prompt, a render, a value you filled in, or a token. There is no other telemetry, and no account.

06Questions

The questions worth asking first.

Why not paste the short prompt and let the model work it out?+
On a strong model, do exactly that. We measured no correctness gain on Claude Opus 5, and the page above says so. On a cheap or local model the picture is different: the raw seed fabricated details it could not see and skipped the test it was asked for, and the render stopped both. If you run open-weight models and find them unreliable, that is who this is for.
Does targeting GPT or Llama call OpenAI or Meta?+
No. A target is data: a profile saying how to prompt that model, built from the vendor's published guidance. The only thing that calls a model is the enhancer, and you choose it. The default shells out to the claude CLI already on your Mac, so there is no API key and no extra spend. --enhancer anthropic uses the official SDK; --enhancer openai takes any OpenAI-compatible endpoint, including one on your own machine.
What does it cost?+
Nothing to install; the code is MIT. Building a render is one enhancer call, about a minute of wall clock, using whatever backend you configured. Copying costs nothing and works offline, because the render is already a file. build skips anything whose seed and guidance have not changed.
What leaves my Mac?+
Two things, both on your command: fetching a vendor's guidance page when you refresh it, and the enhancer call when you build. The MCP server binds to loopback and cannot be reached from the network. The app checks for updates through a Sparkle feed. Crash reporting is off unless you opt in, and never includes prompt text.
Can I use it without the app?+
Yes. The Python package is the product; the app is a front end to it. python3 -m promptlib gives you list, build, copy, match and the local web page, with no dependencies beyond the standard library. The app adds the global hotkey, pasting into the frontmost window, and the MCP server.
Why files in git and not a database or a sync service?+
Prompts change slowly and need to be on several computers, including ones that were asleep when a change happened. Git already does history, backup, sharing and conflict resolution without a server, and a render is prose, so a diff of it is readable. A database would add a schema, a migration path, and a second way for two machines to disagree.
Who is this for, and who made it?+
One person built it for their own daily use, and the repository is open so you can see exactly what it does. There is no company, no support desk and no roadmap promise. If it is useful to you, the issue tracker is where to say so, and that is also how it will get better.
