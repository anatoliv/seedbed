**Key change in `showMenu()`:**

```swift
private func showMenu() {
    guard let button = statusItem.button else { return }
    button.highlight(true)
    makeMenu().popUp(positioning: nil,
                     at: NSPoint(x: 0, y: button.bounds.height + 5),
                     in: button)
    button.highlight(false)
}
```

`popUp` runs its own tracking loop and returns when the menu is dismissed, so it's safe to call from inside the button's action — and `statusItem.menu` never gets touched, which removes the assign/clear race entirely.

**What the tests cover:** the six click-routing cases (right up/down, control-left, plain left, option/command-left, nil event), and menu structure — titles, that "Open" is targeted at the controller and the controller actually responds to the selector, that "Quit" is deliberately untargeted with `terminate(_:)`, and that each call builds a fresh menu.
